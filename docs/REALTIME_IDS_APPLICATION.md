## 1. Overview

The real-time IDS is a **continuously running application** that:

1. Captures live network packets via **Scapy/Npcap**
2. Assembles packets into **bidirectional flows** (5-tuple grouping with idle/absolute timeouts)
3. Extracts **78 CICFlowMeter-compatible features** per completed flow
4. Runs a **three-stage ML inference pipeline** (Binary XGBoost → Multiclass XGBoost → Isolation Forest)
5. Applies **configurable alert rules** and **deduplication** before persisting to SQLite
6. Optionally sends **Telegram push notifications** for high-severity events
7. Exposes **Prometheus metrics** scraped by Grafana for a live 25-panel dashboard
8. Serves a **FastAPI REST + WebSocket interface** for external integrations

### ML Inference Decision Tree

```
Live Network Traffic
        |
        v
Packet Capture (Scapy/Npcap - TCP/UDP/ICMP)
        |
        v
Flow Manager
        |  Aggregates packets by 5-tuple (src_ip, dst_ip, src_port, dst_port, protocol)
        |  until TCP FIN/RST received OR idle (60s) / absolute (300s) timeout
        |
        v
Feature Extractor
        |  Computes 78 statistical features over the completed flow
        |  NaN values filled with per-feature training medians
        |
        v
[Stage 1] XGBoost Binary Classifier
        |  Input:  78-feature vector
        |  Output: P(attack) in [0.0, 1.0]
        |
        +-- P(attack) < 0.8624 --------> BENIGN (early exit, ~84% of all flows)
        |
        +-- P(attack) >= 0.8624
                |
                +---------------------------+
                v                           v
   [Stage 2] XGBoost              [Stage 3] Isolation Forest
   Multiclass (15-class softmax)  Anomaly Score (0 to 1)
   Output: attack type + conf.    Output: anomaly_score + is_anomaly flag
                |                           |
                +-----------+---------------+
                            v
                    Severity Scorer
                    combined = (attack_prob x 0.8) + (iso_score x 0.2)
                    CRITICAL >= 0.95 | HIGH >= 0.85 | MEDIUM >= 0.70 | LOW >= 0.0
                            |
                            v
                    Alert Manager
                    AlertRules --> Dedup (60s window) --> SQLite
                    --> Telegram (if enabled, severity >= min_severity)
                            |
                            v
                    Prometheus Counter/Histogram/Gauge update
                    --> Grafana refreshes every 5 s
                    --> FastAPI WebSocket /stream push
```

## 6. Running the IDS

### Step 1 — Find Your Network Interface

```powershell
venv\Scripts\python.exe src\main.py --list-interfaces
```

This prints all available Npcap interfaces with their NPF GUIDs. Use the GUID of your active adapter.

**Example output on this machine:**

| NPF GUID | Adapter | Status | Use? |
|---|---|---|---|
| `{E2D51F95-...}` | **MediaTek MT7921 Wi-Fi 6** (10.157.x.x) | Up | Use this |
| `{3459A679-...}` | ExpressVPN TAP | Disconnected | No |
| `NPF_Loopback` | Loopback (127.0.0.1) | -- | Test only |

### Step 2 — Start the IDS

```powershell
# Standard run (API active on port 8000, 1 inference worker)
venv\Scripts\python.exe src\main.py --interface "\Device\NPF_{E2D51F95-981B-4D72-889D-15319DF94403}"

# High-throughput (4 inference workers, ~2,700 flows/sec)
venv\Scripts\python.exe src\main.py --interface "\Device\NPF_{E2D51F95-981B-4D72-889D-15319DF94403}" --workers 4

# Custom API port and debug logging
venv\Scripts\python.exe src\main.py --interface "\Device\NPF_{E2D51F95-981B-4D72-889D-15319DF94403}" --api-port 8080 --log-level DEBUG

# TCP-only capture filter
venv\Scripts\python.exe src\main.py --interface "\Device\NPF_{E2D51F95-981B-4D72-889D-15319DF94403}" --filter "tcp"
```

### All CLI Options

```
--interface  / -i    Network interface name (NPF GUID or adapter name)
--workers    / -w    Inference worker threads (default: 1, use 4 for ~2700 flows/s)
--log-level  / -l    DEBUG | INFO | WARNING | ERROR  (default: INFO)
--metrics-port / -m  Prometheus endpoint port (default: 9090)
--api                Start FastAPI REST/WebSocket server (enabled by default)
--api-port           FastAPI port (default: 8000)
--list-interfaces    Print available network interfaces and exit
--filter             BPF capture filter string (default: "ip")
```

### Step 3 — Stop the IDS

```
Press Ctrl+C
```

The system flushes all in-progress flows and prints a session summary before exiting cleanly.

## 8. Runtime Configuration (`config.json`)

All settings take effect on the **next IDS startup** — no code changes required.

```json
{
    "binary_threshold": 0.50,
    "alert_min_severity": "LOW",
    "alert_min_confidence": 0.50,
    "alert_suppressed_types": [],
    "alert_suppressed_ports": [],
    "alert_dedup_window_s": 60,
    "telegram": {
        "enabled": false,
        "bot_token": "",
        "chat_id": "",
        "min_severity": "HIGH"
    }
}
```

### Detection Sensitivity

| Key | Default | Effect |
|---|---|---|
| `binary_threshold` | `0.50` | XGBoost attack probability cutoff. Lower = more sensitive / Higher = stricter. |
| `alert_min_severity` | `"LOW"` | Set `"MEDIUM"` on noisy networks to reduce alert volume. |
| `alert_min_confidence` | `0.50` | Minimum `P(attack)` required to generate an alert. |

### Alert Suppression

| Key | Default | Effect |
|---|---|---|
| `alert_suppressed_types` | `[]` | e.g. `["Bot"]` — silence specific attack types globally. |
| `alert_suppressed_ports` | `[]` | e.g. `[80, 443]` — silence alerts on specific destination ports. |
| `alert_dedup_window_s` | `60` | Seconds before the same `(src_ip, dst_ip, attack_type)` can re-alert. Prevents flood from 1000 DDoS flows/sec generating 1000 alerts. |

### Alert Rule Evaluation Order

```
1. is_attack check         (BENIGN flows never alert)
2. minimum severity gate   (alert_min_severity)
3. minimum confidence gate (alert_min_confidence)
4. suppressed attack types (alert_suppressed_types)
5. suppressed ports        (alert_suppressed_ports)
```

If ALL rules pass, the flow is stored as an Alert in SQLite.

## 9. Telegram Notifications

The IDS can push real-time Telegram messages for qualifying alerts using only Python's built-in `urllib` — no third-party library required.

### Setup

1. Open Telegram and message **[@BotFather](https://t.me/BotFather)** — `/newbot` — copy the **bot token**.
2. Message **[@userinfobot](https://t.me/userinfobot)** — copy your **chat ID**.
3. Edit `config.json`:

```json
"telegram": {
    "enabled": true,
    "bot_token": "<your-bot-token>",
    "chat_id": "<your-chat-id>",
    "min_severity": "HIGH"
}
```

4. Restart the IDS.

### Telegram Configuration

| Key | Default | Description |
|---|---|---|
| `telegram.enabled` | `false` | Set `true` to activate push notifications. |
| `telegram.bot_token` | `""` | Token from @BotFather. |
| `telegram.chat_id` | `""` | Your personal or group chat ID. |
| `telegram.min_severity` | `"HIGH"` | Only sends notifications for alerts at this severity or above. |

### Message Format

```
ALERT

Attack Type: DDoS
Source IP: 192.168.1.45
Destination IP: 10.0.0.1
Confidence: 97%
Severity: HIGH
```

> The `AlertManager` dispatches a **daemon thread** per qualifying alert — Telegram I/O never blocks the detection pipeline. Set `min_severity` to `"CRITICAL"` on high-traffic networks to avoid notification spam.

# Tail the live IDS log

### Alert Schema (SQLite)

| Column | Type | Description |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | Auto-increment alert ID |
| `timestamp` | TEXT | ISO-8601 UTC time of detection |
| `src_ip` | TEXT | Source IP address |
| `dst_ip` | TEXT | Destination IP address |
| `src_port` | INTEGER | Source port (0 for ICMP) |
| `dst_port` | INTEGER | Destination port (0 for ICMP) |
| `protocol` | INTEGER | IP protocol (6=TCP, 17=UDP, 1=ICMP) |
| `attack_type` | TEXT | Multiclass label (e.g. "DDoS", "PortScan") |
| `attack_probability` | REAL | Binary XGBoost confidence [0.0-1.0] |
| `attack_confidence` | REAL | Multiclass softmax max [0.0-1.0] |
| `iso_score` | REAL | Isolation Forest anomaly score [0.0-1.0] |
| `severity` | TEXT | LOW / MEDIUM / HIGH / CRITICAL |
| `latency_ms` | REAL | End-to-end predict_flow() latency |

## 14. Troubleshooting

| Problem | Fix |
|---|---|
| `ModuleNotFoundError: scapy` | Run `venv\Scripts\pip.exe install -r requirements.txt` |
| `PermissionError` on packet capture | Run PowerShell/terminal as Administrator |
| No packets captured | Confirm the interface GUID matches `--list-interfaces` output |
| `FileNotFoundError` for `.pkl` files | Ensure training pipeline has been run — all `models/` artifacts must exist |
| Prometheus target shows **DOWN** | Ensure IDS is running with `--metrics-port 9090` |
| `host.docker.internal` not resolving | Restart Docker Desktop |
| Grafana shows **No Data** | Wait 10-15 s after IDS starts; check Prometheus target at `localhost:9091/targets` |
| SQLite panel is empty | Alerts only appear after the first qualifying attack is detected |
| Port 3000 already in use | Edit `docker-compose.yml`: change `"3000:3000"` to `"3001:3000"` |
| Port 9091 already in use | Edit `docker-compose.yml`: change `"9091:9090"` to `"9092:9090"` |
| Telegram notifications not arriving | Verify `enabled: true`, correct `bot_token` and `chat_id`; check `min_severity` |
